# Qwen3-4B 与 Qwen3-1.7B 工具调用能力核验

核验日期：2026-10-25

## 结论

Qwen3-4B 与 Qwen3-1.7B 的官方后训练 checkpoint 都支持 tool calling。两者使用同一套 Qwen3 工具调用 chat template，能够读取工具 schema，并生成 `<tool_call>` JSON。

这里的“支持”包含三层含义：

```text
模型权重层
  Qwen3-4B / Qwen3-1.7B 经过 post-training
  官方声明支持 thinking 与 non-thinking 两种模式下的外部工具集成

Chat template 层
  template 接受 tools 参数
  将工具定义渲染进 <tools>...</tools>
  训练模型按 <tool_call>{...}</tool_call> 格式输出调用

运行框架层
  Transformers、Qwen-Agent、Ollama、vLLM 等负责加载模型
  Host 负责解析 <tool_call>、执行真实函数、把结果回填给模型
```

模型本身不会直接连接 MCP Server。MCP Host 需要把 MCP Server 提供的工具转换成模型可读的 tool schema，再把模型的调用意图交给 MCP Client/Server 执行。

## 实际调用格式

假设 Host 提供一个设置冰箱温度的工具：

```json
{
  "type": "function",
  "function": {
    "name": "set_fridge_temperature",
    "description": "设置冰箱指定分区的目标温度",
    "parameters": {
      "type": "object",
      "properties": {
        "zone": {
          "type": "string",
          "enum": ["冷藏室", "冷冻室"]
        },
        "temperature": {
          "type": "number"
        }
      },
      "required": ["zone", "temperature"]
    }
  }
}
```

Qwen3 chat template 会把工具 schema 放进 `<tools>` 区域，模型随后输出：

```text
<tool_call>
{"name": "set_fridge_temperature", "arguments": {"zone": "冷藏室", "temperature": 5}}
</tool_call>
```

Host 解析调用并执行 MCP 工具，然后把结果回填：

```text
<tool_response>
{"success": true, "target_temperature": 5}
</tool_response>
```

模型再根据 `<tool_response>` 生成最终回答。Qwen3 的 template 还支持在一条 assistant 消息中生成多个 `<tool_call>`，即并行工具调用。

## 接入时容易混淆的边界

```text
模型会生成工具调用文本
  ≠
OpenAI Chat Completions API 一定会自动返回结构化的 tool_calls 字段
```

如果直接使用 Transformers `generate`，得到的是带 `<tool_call>` 的文本，需要上层解析。如果使用 vLLM、Ollama 或 Qwen-Agent，工具调用是否表现为结构化字段，取决于运行时版本、启动参数和解析器。

Qwen-Agent README 对原始 Qwen3 模型的说明是：推荐由 Qwen-Agent 解析工具输出，不建议直接给 vLLM 加 `--enable-auto-tool-choice --tool-call-parser hermes`。因此接入 Qwen3 原始版本时，Qwen-Agent 是官方给出的稳妥路径。Qwen3-Coder 的推荐配置不同，不能把两者的 parser 设置混用。

Qwen3 技术报告使用 BFCL v3 测试函数调用能力，两版模型的分数为：

| 模型 | Thinking 模式 | Non-thinking 模式 |
|---|---:|---:|
| Qwen3-4B | 65.9 | 57.6 |
| Qwen3-1.7B | 56.6 | 52.2 |

这组结果说明 1.7B 的 BFCL 分数低于 4B，但并非“没有工具调用能力”。BFCL 分数只代表官方基准表现，不能直接代替具体 MCP 工具集上的成功率。

## 对本地端侧模型的判断

Qwen3-4B 的官方 BFCL 分数更高，更适合承担多工具、多轮智能家居操作。1.7B 具备工具调用训练和格式支持，但在复杂 schema、设备名相似、参数容易混淆的场景下需要实测，不能仅凭“支持 tools”推定它在任意 MCP 工具集上都有稳定成功率。

对小模型更合理的使用方式是：

```text
设备 profile 和工具列表先压缩
  ↓
一轮只暴露少量名称明确、参数简单的工具
  ↓
模型输出 <tool_call>
  ↓
Host 做 schema 校验和权限检查
  ↓
调用 MCP Server
  ↓
把精简结果回填模型
```

当前结论来自官方模型卡、官方 tokenizer/template 和官方适配文档，尚未在本机下载权重进行推理解码实测。业务落地时还应记录模型在自定义工具集上的工具选择准确率、参数准确率和多轮完成率。
