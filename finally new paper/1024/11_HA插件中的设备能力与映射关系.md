# 11：HA 插件中的设备能力与映射关系

核验日期：2026-10-29

本文不整理型号清单，重点回答：从插件源码里能否看出设备有哪些功能，以及这些功能怎样落到 HA Entity、State 和 Service。

## 0 结论

```text
插件真正提供的是能力解释规则

协议字段或云端属性
  ↓
设备族判定
  ↓
HA Entity / State / Attribute
  ↓
HA Service / 厂商 Command
  ↓
统一 Capability
```

以空调为例，插件里反复出现的能力是：

```text
开关
运行模式
当前温度
目标温度
风速
摆风 / 风向
特殊模式
能耗与滤芯等附加状态
```

一个空调不一定等于一个 `climate` Entity。插件常把同一台设备拆成：

```text
climate
  主状态、模式、温度、风速

number
  目标温度、定时

switch
  电源、ECO、睡眠、Boost、辅热、自清洁

select
  某方向的扫风、程序、档位

sensor
  当前温度、室外温度、湿度、能耗

fan
  独立新风或 Matter Fan Control
```

做统一语义时，必须按 Device 聚合 Entity，再把它们还原成 Capability；不能把一个 HA domain 直接当成一个设备能力。

## 1 从插件里能看到哪些信息

| 信息 | 例子 | 来源 |
|---|---|---|
| 设备族 | Air Conditioner、Refrigerator | Midea type、Xiaomi MIoT device type、Tuya category、Matter Device Type |
| 能力是否存在 | 是否有风速、摆风、门状态 | 字段组合、capability 列表、Cluster FeatureMap |
| HA 表面 | `climate`、`number`、`sensor` | 插件的 platform 映射和 Entity Description |
| 读写属性 | 当前温度只读，目标温度可写 | MIoT access、Entity setter、service |
| 参数范围 | 17–30°C、1°C 步长、低/中/高 | value range、enum、allowed values、Matter min/max |
| 执行路径 | `climate.set_temperature` 最终写什么 | 插件 setter、API command、DPCode、Matter Cluster Command |

插件证据可分为三种：

```text
静态映射
  Midea 的 appliance type 和字段表
  hOn 的固定控件表

规范驱动
  Xiaomi MIoT SPEC
  Matter Device Type / Cluster / Attribute

运行时能力集合
  SmartThings capability
  Home Connect program/option/constraint
  Tuya DP wrapper
```

其中 Matter 给出了最正式、机器可读的约束；厂商插件则补充了标准的映射方式和品牌特有能力。

## 2 空调：插件能看到什么

### 2.1 横向映射

| 来源 | 如何识别空调 | 主要输出 | 能看到的能力 |
|---|---|---|---|
| Midea | 固定 appliance type `0xAC` | `climate` + 多个 switch/sensor/select | 开关、六种模式、目标/当前温度、五档风速+auto、水平/垂直摆风、辅热、ECO、睡眠、Boost、自然风 |
| Xiaomi | MIoT `air-conditioner` service 的必需属性组合 | 动态组装 `climate` | `on`、`mode`、`target-temperature` 必需；`fan-control`、`environment`、扫风为可选 |
| hOn | 固定 appliance key | `climate` + `number` + switch/select/sensor | 主温控、目标温度、风速、水平/垂直风向、Night/Rapid/Eco/Self Clean 等 |
| LG ThinQ | `DeviceType.AIR_CONDITIONER` | `climate` + 定时 `number` | 模式、目标/当前温度、fan mode、swing、preset、湿度，具体能力随运行时数组出现 |
| SmartThings | 一组 capability 全部存在 | `climate` | 模式、开关、风速、目标温度、摆风、富预设模式、需求响应属性 |
| Home Connect | AC ProgramKey 是否存在 | 条件性 `climate` | auto/cool/dry/fan/heat、automatic/manual fan、Active Clean；当前源码未实现温度功能 |
| Tuya | category `kt` | 动态 `climate` | 开关、模式、温度、风速、摆风、preset、湿度都由运行时 DP wrapper 决定 |
| Daikin / MELCloud / FGLair / Hisense | 厂商协议声明 | 常规 `climate` | 当前/目标温度、模式、风速、摆风，部分支持 preset |
| Matter | `Room Air Conditioner 0x0072` | `climate` + 条件性 `fan`/sensor | On/Off、Thermostat、可选 Fan Control、Temperature/Humidity Measurement |

### 2.2 核心功能的典型映射

| 统一能力 | 常见 HA 表面 | 插件差异 |
|---|---|---|
| 开关 | `climate`，有时另带 `switch` | Midea 与 hOn 可能重复暴露 |
| 运行模式 | `climate.hvac_mode` | Midea 固定枚举；Xiaomi/Tuya 从 value list 或 DP 动态读 |
| 目标温度 | `climate.target_temperature`，有时另带 `number` | hOn 同时出现 climate 和 number |
| 当前温度 | `climate.current_temperature` 或独立 `sensor` | Xiaomi、LG 放 climate；Midea 同时可由 climate 提供；hOn 主要用 sensor |
| 风速 | `climate.fan_mode`，有时是独立 `fan` | Matter Fan Control 通常生成独立 fan Entity |
| 摆风 | `climate.swing_mode`、switch 或 select | Midea/Xiaomi 会把两个 bool 合成四种模式；hOn 用两个 select；Matter 用 RockSetting |
| 特殊模式 | preset、switch 或 select | ECO、Sleep、Boost、Self Clean、Aroma、WindFree 等没有统一位置 |

直接例子：

```text
Midea fan_speed
  20   → Silent
  40   → Low
  60   → Medium
  80   → High
  100  → Full
  102  → Auto

Xiaomi MIoT mode
  off / idle  → HVAC OFF
  auto        → HVAC AUTO
  cool        → HVAC COOL
  heat        → HVAC HEAT
  dry         → HVAC DRY
  fan         → HVAC FAN_ONLY

Midea swing_vertical + swing_horizontal
  false + false → off
  true  + false → vertical
  false + true  → horizontal
  true  + true  → both
```

### 2.3 几个实现差异

```text
Midea
  固定字段映射最完整
  climate 已经承载 power/mode/temp/fan/swing/preset
  另有一些 switch/sensor 是重复或扩展入口

Xiaomi
  先判断必需 service/property
  再读取 value-range 和 value-list
  相同插件可以适配不同 MIoT SPEC
  可选 fan-control 不存在时，就不能输出风速或扫风能力

hOn
  主 climate 之外有大量显式 switch/select
  说明“开关、模式、摆风”不一定都适合压进 climate
  很适合区分 common 与 custom

LG ThinQ
  能力由 data.hvac_modes、fan_modes、swing_modes 等运行时数组生成
  air_clean、aroma、energy_saving 被映射成 preset
  定时被拆成 number，而不是塞回 climate

SmartThings
  必须同时具备模式、风速、switch、温度测量和 cooling setpoint 才生成 AC climate
  可选 capability 再增加 swing、preset、需求响应

Home Connect
  HVAC 模式来自 ProgramKey
  climate 存在不代表目标温度可写
  当前 AC climate 明确没有温度功能

Tuya
  category 只回答“是不是空调”
  fan、swing、temperature、humidity 是否出现，取决于实际 DP wrapper
```

## 3 Matter 对空调的约束

本地 Matter 1.6：

```text
Room Air Conditioner
  Device Type 0x0072

必须实现
  On/Off 0x0006
  Thermostat 0x0201

可选
  Fan Control 0x0202
  Temperature Measurement 0x0402
  Relative Humidity Measurement 0x0405
  HEPA Filter Monitoring 0x0071
  Activated Carbon Filter Monitoring 0x0072
  Thermostat User Interface Configuration 0x0204
```

HA 映射结果：

```text
On/Off + Thermostat
  → climate

Fan Control
  → 独立 fan Entity

Temperature Measurement
  → temperature sensor

Relative Humidity Measurement
  → humidity sensor
```

Thermostat 能看到：

```text
SystemMode
  off / auto / cool / heat / dry / fan-only 等

OccupiedCoolingSetpoint
OccupiedHeatingSetpoint
  单设定点或冷热双设定点

Min/Max Setpoint Limit
  设备真实允许范围

FeatureMap
  是否真的支持 Heating、Cooling、Auto 等

Presets
  occupied / unoccupied / sleep / wake / vacation 等
```

Fan Control 能看到：

```text
PercentSetting / PercentCurrent
  连续百分比风速

SpeedSetting / SpeedCurrent
  多档风速

FanMode
  off / low / medium / high / auto 等

RockSetting
  → HA fan.oscillate

WindSetting
  → natural_wind / sleep_wind

AirflowDirection
  → forward / reverse
```

Matter 没有把厂商常见的“水平摆风”和“垂直摆风”规定成两个独立属性。它只有 rocking、wind 和 airflow direction。因此统一模型可以保留 `swing_vertical`、`swing_horizontal`，但 Matter 实例通常只能提供较粗的 `oscillation`。

## 4 冰箱：一个设备通常拆成多个 Entity

| 来源 | 当前温度 | 目标温度 | 门/告警 | 模式与快捷功能 |
|---|---|---|---|---|
| Xiaomi | `sensor` | `number` | event 或条件性 sensor | 取决于 MIoT SPEC |
| Midea 0xCA | 各区 `sensor` | setting temperature 也映射成 `sensor` | `binary_sensor` | mode 字段存在，但当前 Entity 映射有限 |
| hOn | `sensor` | 各区 `climate` + `number` | `binary_sensor` | Super Cool/Freeze、Auto-Set 等 switch |
| LG ThinQ | 当前温度入口未稳定找到 | `number` | `binary_sensor` | Express/Fresh Air 等 switch/select |
| Home Connect | 当前温度入口未稳定找到 | 各区 `number` | `binary_sensor` + alarm sensor | Super/ECO/Vacation/Sabbath 等 switch |
| Miele | 每温区 `climate` | 温区内 `climate` | `binary_sensor` | Super Cooling/Freezing switch |
| Whirlpool | 未稳定找到 | 温度等级 `select` | 未稳定找到 | 云设备字段 |
| GE SmartHQ | 取决于 service | `number/select` | `door` service | ERD 与 service 扩展 |
| SmartThings | temperature capability 条件性提供 | refrigeration setpoint `number` | component `binary_sensor` | ice maker 等 switch |
| Tuya | DP wrapper | DP wrapper | DP wrapper | DP wrapper |
| Matter | 条件性 `sensor` | Temperature Control `number` | Refrigerator Alarm | Mode select、filter 可选 |

最重要的映射现象：

```text
同一个 target_temperature
  在米家是 number
  在 hOn 是 climate + number
  在 Home Connect 是 number
  在 Whirlpool 是温度等级 select
  在 Midea 当前是只读 sensor
  在 Matter 是 TemperatureControl → number

同一个 door
  binary_sensor
  event
  alarm bit
```

所以不能根据字段名 `setting temperature` 判断它一定可写，也不能根据一个 `sensor` 判断设备没有温控能力。必须同时查看 platform、可写 access 和 service。

Matter 冰箱的结构更明确：

```text
Refrigerator 0x0070
  └─ Temperature Controlled Cabinet 0x0071
       └─ Temperature Control 0x0056
            TemperatureSetpoint
            MinTemperature
            MaxTemperature
```

映射：

```text
Temperature Control
  → HA number

Temperature Measurement
  → HA sensor

Mode.CurrentMode + SupportedModes
  → HA select

Refrigerator Alarm.DoorOpen
  → diagnostic binary_sensor
```

Matter 冰箱可以包含多个 cabinet endpoint。一个冰箱有冷藏、冷冻、变温区时，现实中可能是多个 number/sensor/select Entity，语义层必须按 Device 聚合，并给 Capability 加 `zone`。

Matter 冰箱的边界：

```text
目标温度控制是标准能力
当前温度是 optional
模式是 optional
门开告警是 optional
速冷/速冻没有统一快捷字段
主电源开关不是 Refrigerator 的强制能力
```

## 5 对 MCP 收缩的结论

插件证据支持以下结构：

```text
空调
  common.observe
    power
    current_temperature
    humidity
    online

  common.control
    target_temperature
    hvac_mode
    fan_speed

  common.action
    turn_on
    turn_off

  custom
    swing_vertical
    swing_horizontal
    natural_wind
    sleep_mode
    eco_mode
    boost_mode
    self_clean
    fresh_air
    display
    energy_statistics

冰箱
  common.observe
    各温区 current_temperature
    door_state
    fault_state
    online

  common.control
    各温区 target_temperature

  custom
    super_cool
    super_freeze
    holiday_mode
    ice_maker
    sabbath_mode
    filter_state

  hidden
    calibration
    factory_reset
    network_config
    raw_property_write
```

最终能力按交集生成：

```text
Profile 允许能力
  ∩
插件能够解释的字段
  ∩
设备实例真实存在的能力
  =
MCP 可见能力
```

例如：

```text
Profile 允许空调有 swing
  但该米家设备没有 horizontal-swing / vertical-swing
  → 不输出 swing

Matter 设备声明 Room Air Conditioner
  但没有 Fan Control Cluster
  → 不输出风速和 rocking

Home Connect 生成 AC climate
  但当前实现没有温度功能
  → 不输出 target_temperature
```
